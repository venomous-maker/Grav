# Integer

`import "std/types"` (included in `import "std"`) · namespace `std.types`

`Integer` holds what whole numbers can do beyond arithmetic. Every static method
whose first parameter is the number is also a method of any integer value, so
`n.toHex()` and `Integer.toHex(n)` are the same direct call.

```grav
import "std"

fn main() {
    let n = 255
    print(n.toHex() + " " + 255.toBinary())
    print(Integer.parse("42") + 1)
    print(1234567.grouped() + " " + 22.ordinal() + " " + 7.padded(3))
    print("${(-7).abs()} ${12.gcd(18)} ${n.bitCount()} ${1000.nextPowerOfTwo()}")
    let xs: Array<int> = [5, 3, 9]
    xs.sortBy(Integer.descending)
    print(xs)
    try { print(Integer.MAX.addExact(1)) } catch (e: ArithmeticError) { print(e.message()) }
}
```

Output:

```text
ff 11111111
43
1,234,567 22nd 007
7 6 8 1024
[9, 5, 3]
integer overflow: 2147483647 + 1
```

- **Parsing**: `Integer.parse(s)` (an int, range-checked), `parseLong`,
  `parse(s, base)` (2 to 36; `0xff` too), `parseOr`, `tryParse` (null when
  it is not a number), `isValid`. A cast does the same: `"42" as int`.
- **Comparators** (`compare`, `descending`) fit `sortBy` and `Sort`; checked
  arithmetic (`addExact`, `multiplyExact`, ...) throws `ArithmeticError`
  instead of wrapping.
- int and long versions exist where the result's width matters (`abs`, `min`,
  `bitCount`, `rotateLeft`), so `n.abs()` stays an int for an int.
