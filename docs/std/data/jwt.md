# JWT

`import "std/data"` (included in `import "std"`) · namespace `std.data`

JSON Web Tokens (RFC 7519) signed with HMAC (HS256/384/512), RSA (RS256/384/512),
ECDSA (ES256/384/512) or Ed25519 (EdDSA), and key sets (JWKS) as identity
providers publish them. The tokens interoperate with other implementations
(checked against PyJWT both ways).

```grav
import "std"

fn main() {
    let key = JwtKey.of(CryptoKey.generate("p256")).withKid("2026-11")
    let claims = Json.object()
    claims.set("sub", "42")
    claims.set("aud", "app")
    claims.set("exp", Time.now() + 3600)
    let token = Jwt.sign(claims, key)
    print(Jwt.decode(token).header.toJson())

    // what a verifier holds: the public key set
    let keys = Jwks.parse(new Jwks().add(JwtKey.fromJwk(key.toJwk())).toJson().toJson())
    let opts = new JwtOptions()
    opts.audience = "app"
    print(Jwt.verifyWith(token, keys, opts).getString("sub", ""))

    try {
        Jwt.verify(token + "x", JwtKey.fromJwk(key.toJwk()))
    } catch (e: JwtException) {
        print(e.message())
    }
}
```

Output:

```text
{"alg":"ES256","typ":"JWT","kid":"2026-11"}
42
the signature does not match
```

Verifying checks, in order: the header's algorithm is the key's own (so `none`,
or HS256 presented to an RSA key, is refused), the signature, `exp` (required
unless `requireExpiry` is off) and `nbf` with `leewaySeconds` of slack, then
`iss` and `aud` when `JwtOptions` names them. Every failure is a
`JwtException`. `Jwks.parse` reads a provider's `jwks_uri` document (fetch it
with `HttpClient`); `verifyWith` picks the key by the token's `kid`.
