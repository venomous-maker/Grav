# TOML

`import "std/data"` (included in `import "std"`) · namespace `std.data`

TOML 1.0 (the format of `grav.toml`, `Cargo.toml` and `pyproject.toml`) read
into the same `JsonValue` tree as JSON, so the rest of the program uses it the
same way: tables are objects, arrays are arrays, and dates and times are kept
as their text. `Toml.stringify` writes a `JsonValue` object back: plain values
first, then `[tables]` and `[[arrays of tables]]` (dates come out as quoted
strings). Malformed input, or a key or table defined twice, is a `ValueError`
naming the line. Its results match Python's `tomllib`.

```grav
import "std"

fn main() {
    let cfg = Toml.parse("name = \"shop\"\n[server]\nport = 8080\nhosts = [\"a\", \"b\"]\n[[workers]]\nqueue = \"mail\"\n")
    print(cfg.getString("name", ""))
    print(cfg.get("server").get("port").asLong() + 1)
    print(cfg.get("workers").at(0).getString("queue", ""))
    print(Str.trimEnd(Toml.stringify(cfg)))
}
```

Output:

```text
shop
8081
mail
name = "shop"

[server]
port = 8080
hosts = ["a", "b"]

[[workers]]
queue = "mail"
```
