# generator

`import "std/concurrency"` (included in `import "std"`) · namespace `std.concurrency`

A function that returns `Iterator<T>` and uses `yield` is a *generator*: the
compiler turns its body into a `Generator<T>`, which runs it one `yield` at a
time as a loop asks for values. You do not usually name these classes; they are
what a generator is made of.

```grav
import "std"

// The lines of a text that are not comments, numbered from 1.
fn code(text: string) -> Iterator<string> {
    let n = 0
    for (line in Str.lines(text)) {
        n += 1
        if (Str.startsWith(Str.trim(line), "#")) { continue }
        yield "${n}: ${line}"
    }
}

fn main() {
    for (l in code("a = 1\n# note\nb = 2")) { print(l) }
}
```

Output:

```text
1: a = 1
3: b = 2
```

How it runs:

- The body starts at the loop's first step and stops at each `yield` until the
  next is asked for, so it never runs at the same time as the loop. Its locals
  keep their values between steps.
- The body runs on a thread of its own, which costs a thread switch per value.
  That suits values that come from files, sockets, queries or long computations;
  for tight numeric loops, write an `Iterator<T>` class or a plain loop.
- A loop that stops early drops the generator: the paused `yield` throws
  `GeneratorClosed`, so the body's `finally` blocks run and its thread ends.
- An exception the body throws comes out of the loop step that was waiting for a
  value.
- `yield` belongs to the function or method itself: a lambda inside it cannot
  yield.
